# Coupling

> In Software Design, Coupling tells us **how much one class depends on another class** to perform its work. 

It is of two types

1. Tight Coupling
2. Loose Coupling

## Tight Coupling

> Tight coupling means when one class directly creates or strongly depends on another concrete class.

**Disadvantages**

- Hard to maintain
- Hard to test
- Difficult to replace implementations
- More code changes required

## Loose Coupling

> Loose coupling means when classes depend on **abstractions (interfaces/abstract classes)** instead of concrete classes. 

# Introduction to Spring

> Spring is a framework; it is not a programming language 

Spring is a **Java framework** used for building enterprise and web applications.

- It helps developers write **clean, modular, and testable code**.

Spring provides built-in support for:

- Database integration
- Security
- Messaging
- REST APIs
- And much more

**Why Spring?**

Spring simplifies Java application development by reducing boilerplate code.

It supports multiple application architectures, including:

- Web applications
- Microservices
- Cloud-native applications

# IOC

> Object creation and dependency management are handled by Spring Container instead of the programmer.



> In Spring, IoC means transferring control of object creation and dependency management from application code to the Spring container, which creates, configures, and manages beans automatically.

## Stereotype Annotations

These annotations are used to create Spring beans automatically in the application context (Spring Ioc container(

1. **@Component** : It is used to tell Spring: “This class should be managed by the Spring container as a bean.”
2. **@Primary**: @Primary is a Spring annotation used to mark a bean as the default bean for dependency injection when multiple beans of the same type are available in the IoC container 
3. @**Qualifier**: @Qualifier is a Spring annotation used to **specify the exact bean to inject** when multiple beans of the same type exist in the IoC container.
